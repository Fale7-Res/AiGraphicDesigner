# Next milestone: Classical CV, pretrained ML, or hybrid geometry

**Recommendation only; owner approval required.** No weights were downloaded, no model trained/inferred/integrated, and no neural dependency installed in this cycle. Current frozen candidates are unchanged.

The current evidence argues for a controlled hybrid comparison, not an assumption that ML solves vector reconstruction. Paired source evidence found long Fine Features traces, but the cubic fitter rejected them because of real overshoot. ML cannot fix that serializer/fitter contract. Conversely, incomplete crown material boundaries and separating lighting from structure may benefit from learned context that local contrast lacks. These are distinct tasks.

| Candidate | Potential benefit | Risk and hardware/integration implications |
|---|---|---|
| Classical paired-boundary/ridge CV | Cheap, source-local, explainable thin support; current implementation runs on CPU | Current test fails Fine vector acceptance and gives sparse Arabic/Shield snippets. Lighting false positives and local-scale ambiguity remain. Requires curve-fitting stability and region/stroke integration. |
| Pretrained DexiNed edge detector via OpenCV ONNX | Learned contour evidence could suppress some noise and supply missing continuity; suitable CPU-first research candidate | It still produces an edge field, not regions, complete curves or glyph topology. Domain shift to metallic logos/Arabic is untested. Official OpenCV model directory states MIT terms; checkpoint provenance/terms must be recorded individually. Current published demo requires OpenCV>=5, unlike this experiment's4.13, so isolate any new runtime and verify compatibility rather than upgrade the baseline. |
| Pretrained SAM2.1 Hiera tiny | Prompted region masks could propose missing crown/component regions rather than only nearby endpoints | Object silhouettes can omit crown ornamentation, bands and letter counters. Uniform prompts may miss small structures; evaluator contours cannot become prompts. Tiny is38.9M parameters; upstream recommends a GPU machine and WSL on Windows. CPU feasibility/latency and local CUDA compatibility need measurement. Code/checkpoints Apache2.0; retain third-party notices. |
| Hybrid | Learned boundary/region proposals plus source-local contrast/width, continuous curve fitting, shared topology guards and renderer QA | Most defensible hypothesis, still unverified. Neural confidence must not bypass topology, internal-component vetoes or source evidence. Keep model proposal quality separate from downstream fitter performance. |

SAM3/3.1 offers concept prompts, but upstream currently specifies modern CUDA requirements, gated checkpoint access and a custom SAM License; it is a higher-cost later alternative, not the first local choice on2GiBhardware.

Proposed future evaluation: freeze the existing four controls plus several unseen licensed logos/Arabic/thin illustrations and one textured photo. Compare classical evidence, learned edges, prompted masks and hybrid proposals using the SAME corrected exporter and downstream fitting/topology controls. First measure missing-component/inner-boundary recall and thin continuity **before fitting**, then post-fit fidelity/holes/crossings/anti-grid. Automatic uniform prompt policy must be frozen; any human-prompted arm is separately disclosed and cannot reuse evaluator annotations. Preserve crown tips/ornament/band vetoes, false joins, negative/shading controls and resource budgets. No training or finetuning initially; model weights/revisions/licenses hashed only after approval. Reject an ML/hybrid arm that only improves silhouette or smoothness while losing interior artwork.
