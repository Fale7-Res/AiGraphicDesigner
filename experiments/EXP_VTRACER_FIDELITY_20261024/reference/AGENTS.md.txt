# AI Graphic Designer — Agent Entry Point & Operating Constitution (`AGENTS.md`)

**الحالة (Status):** ACTIVE CONSTITUTION — اقرأ هذا الملف بالكامل قبل تنفيذ أي خطوة في المشروع.
**طبيعة النظام:** محرك تصميم جرافيكي ذكي متكامل (AI Graphic Designer) يجمع بين توليد الصور المخطط بالطبقات (Scene-Graph Driven Image Generation)، وتفكيك الصور إلى طبقات فيكتور نظيفة (Magic Layers & Clean SVG)، والتعامل الذكي مع النصوص والخطوط (Smart Typography)، والتعديل الجراحي على الطبقات (Layer-Aware Editing).

## 1. التسلسل الإلزامي لبدء أي جلسة (Mandatory Session Startup Sequence)

عند بدء أي محادثة جديدة أو بعد أي عملية ضغط للسياق (Context Compaction)، **يُحظر تماماً** كتابة أي كود أو إصدار افتراضات قبل قراءة ملفات "الذاكرة الخارجية الحية" بالترتيب التالي:

1. `memory/MEMORY_INDEX.md` — الفهرس الرئيسي لذاكرة المشروع (ماذا نبني، ما الذي تم إنجازه، وما هي هيكلة الذاكرة).
2. `memory/session/CURRENT_TASK_CHECKPOINT.md` — نقطة التوقف الحالية (ماذا كنا نفعل في الجلسة السابقة أو قبل الـ Compaction، وما هي الخطوة التالية).
3. `memory/session/ACTIVE_SESSION_WAL.md` — سجل الكتابة المسبقة (Write-Ahead Log) الذي يحفظ كل تفصيلة أو اكتشاف لحظة بلحظة.
4. `memory/ARCHITECTURE_AND_DATA_FLOW.md` — خريطة المعمارية وتدفق البيانات بين الملفات (مين بياخد منين وبيرمي فين).
5. `memory/FUNCTION_REGISTRY.md` — السجل المركزي لجميع الدوال والكلاسات وأرقام أسطرها ومقتطفاتها لمنع تكرار أي دالة (`Zero Duplicated Functions`).
6. `PROJECT_FILE_CATALOG.md` — الفهرس الكامل لجميع ملفات المستودع وعلاقاتها المتبادلة.
7. `docs/product/OWNER_ORIGINAL_VISION.md` — النص الأصلي الحرفي لرؤية المالك (`OWNER_REQUIREMENT` Authority).
8. `memory/findings/FINDINGS_LEDGER.md` — سجل مكتشفات الـ Sub-Agents وحالة مراجعتها وترقيتها.
9. `MASTER_PLAN.md` — خارطة الطريق الشاملة لكافة أجزاء المشروع (الحالة الحالية: `ARCHITECTURE_AND_GOVERNANCE_PREPARATION — NOT_APPROVED`).

## 2. القواعد الذهبية الخمس لمنع أخطاء الـ Vibe Coding والهلوسة (The 5 Iron Laws)

1. **الذاكرة الخارجية الحية وليست مجرد توثيق (`External Brain, Not Passive Docs`):**
   - مجلد `memory/` هو **ذاكرتك الفعلية**. إذا مسحت المحادثة أو جاء مطور أو Agent آخر مكانك، يجب أن يفهم كل شيء حدث منذ أول لحظة في المشروع من خلال قراءة `memory/` دون الحاجة لقراءة آلاف الأسطر من الكود.
2. **التسجيل الفوري قبل ضغط السياق (`Write-Ahead Logging — Anti-Compaction`):**
   - **ممنوع منعاً باتاً** تجميع معلومات أو نتائج بحث أو تفاصيل تقنية في ذاكرة المحادثة والانتظار لنهاية الجلسة لتسجيلها. أي حقيقة، معادلة، قرار، أو سبب خطأ تكتشفه يجب كتابته **فوراً وفي نفس الخطوة** داخل `memory/session/ACTIVE_SESSION_WAL.md` وتحديث `CURRENT_TASK_CHECKPOINT.md`.
3. **حظر القراءة الجزئية للملفات في Antigravity (`Mandatory Full-File Read`):**
   - في بيئة Google Antigravity، **يُحظر** الاعتماد على مقتطفات صغيرة (`snippets`) أو قراءة بضعة أسطر فقط قبل التعديل. قبل تعديل أي ملف برمجي، يجب قراءة الملف **بالكامل من السطر الأول حتى السطر الأخير** (أو على دفعات متتالية كاملة إذا زاد عن 800 سطر)، ومراجعة ملف المرآة الخاص به في `memory/code_mirrors/`.
4. **مرآة الكود وأرقام الأسطر ومنع تكرار الدوال (`1:1 Code Mirror & Line-Number Registry`):**
   - كل ملف برمجي في المشروع له ملف Markdown مقابل في `memory/code_mirrors/<file_path>.md` ومُسجل في `memory/FUNCTION_REGISTRY.md`.
   - أي دالة أو منطق برمجي يُكتب أو يُوثق يجب ذكر **مكانه بالضبط بأرقام الأسطر (`Lines Start–End`)** مع **كتابة الكود الفعلي/المقتطف (`Verbatim Code Snippet`)**، وتوضيح **علاقاته بالملفات الأخرى (بياخد الداتا منين وبيرميها فين)**.
   - قبل كتابة أي دالة جديدة، ابحث في `memory/FUNCTION_REGISTRY.md`؛ إذا وُجدت دالة تؤدي نفس الغرض، أعد استخدامها ولا تكررها.
5. **تقسيم المهام على Sub-Agents مع مراجع مستقل إلزامي (`Sub-Agent Decomposition & Reviewer Gate`):**
   - لا تنفذ المهام المركبة في خيط واحد مزدحم. قسّم المهمة إلى حزم عمل مستقلة (Disjoint Work Packages) عبر الـ Sub-Agents المتخصصين في `.agents/agents/`، ثم استدعِ وجوباً **Sub-Agent المراجع المستقل (`qa-reviewer-auditor`)** لمراجعة الكود، والتأكد من عدم وجود تعارض أو تكرار دوال، ومطابقة أرقام الأسطر في الذاكرة قبل إعلان انتهاء المهمة.

## 4. نطاق المشروع الشامل وعدم تقييد نقطة البداية (`Whole-System Non-Prescriptive Scope`)

تغطي هذه القواعد **المشروع بالكامل** بجميع أوضاعه ومكوناته (توليد الصور بالـ Layers، تفكيك الصور بـ Magic Layers، رسم الـ Clean SVG المجمّع في Groups، التعامل مع الخطوط والنصوص، التعديل على الطبقات، واجهة الـ Canvas، والـ Backend/APIs). لا تفرض هذه القواعد نقطة بداية إجبارية واحدة؛ يتبع الـ Agent توجيه المستخدم المباشر في الجلسة لتحديد أي موديول أو وضع يبدأ بتطويره أو تعديله، مع الالتزام الكامل بقواعد المعمارية والذاكرة في كل خطوة.
